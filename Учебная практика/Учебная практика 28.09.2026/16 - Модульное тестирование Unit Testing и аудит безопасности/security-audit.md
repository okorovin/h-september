# Аудит безопасности: защита от SQL-инъекций

## Что проверялось
Все обращения к БД в коде подсистемы:
- `server/partner-service.js` — окна добавления/редактирования партнёра, списки, история;
- `server/material-service.js` — калькулятор материалов и справочники;
- `server/index.js` — маршруты, принимающие пользовательский ввод.

## Метод проверки
Поиск двух опасных паттернов во всех вызовах `pool.query`:
1. интерполяция переменных в строку запроса (`` `... ${value}` ``);
2. конкатенация строк с данными (`"... " + value`).

Ни одного совпадения не найдено.

## Результат
Все запросы используют **параметризованные аргументы** — значения передаются вторым аргументом `pool.query`, а в тексте запроса стоят плейсхолдеры `$1, $2, ...`. Драйвер `pg` экранирует их сам, конкатенация пользовательского ввода отсутствует.

Примеры из кода:

```js
// partner-service.js — чтение по id
await pool.query('SELECT ... FROM partners WHERE partner_id = $1', [partnerId]);

// partner-service.js — вставка партнёра
await pool.query(sql, values); // sql содержит $1..$7, значения в массиве values

// material-service.js — справочник по id
await pool.query('SELECT coefficient FROM product_types WHERE product_type_id = $1', [productTypeId]);
```

Небезопасная альтернатива (в коде **не используется**):

```js
// так делать нельзя — прямая подстановка открывает SQL-инъекцию
await pool.query(`SELECT ... WHERE partner_id = ${partnerId}`);
```

## Вывод
Подсистема защищена от SQL-инъекций: пользовательский ввод (поля формы партнёра, параметры калькулятора, id в маршрутах) во всех случаях проходит через параметризованные запросы.
